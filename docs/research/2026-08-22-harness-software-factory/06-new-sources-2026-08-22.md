## A. YanXbt — "HERMES AGENT BOT MODE: Full Guide to Building Your AI Team" (18 ago)
https://x.com/IBuzovskyi/status/2089701386887868653 (article 2089647871666671616) — 89k views

- **Bot = Hermes profile.** Same isolated config/memory/skills/credentials under `~/.hermes/profiles/[name]/`. Bot Mode is a UI over profiles — nothing new server-side. Shipped bundled+default-on in Hermes Desktop (Nous Research, 17 ago).
- **Agent Inbox:** every bot has a persistent inbox conversation; inter-bot messages land with attribution (`[Message from agent 'researcher']`). The receiving bot's SOUL.md encodes the protocol: check inbox at start of run → read in order → reply with attribution → only then return to the user's ask.
- **@mentions:** synchronous handoff — active bot forwards, waits, reports back inline.
- **Group chat:** all bots in a team share the same conversation context and read each other ("most multi-agent chat setups don't do this"). Observed spontaneous coordination between bots without prompting. Group chat starts FRESH sessions; workaround: paste a session ID so a bot imports prior context.
- **Cronjobs:** per-bot schedules, visible in one sidebar.
- **Bot HR pattern (the big one):** don't create bots manually — one bot ("bot-hr") reads a project spec, decides team composition, creates each specialist with model-per-role and a SOUL.md that names its teammates. Real example: 4-bot racing-game team, each model choice explained. "Month 3 bot-hr makes better choices than month 1."
- **Interpreter bot pattern:** a bot whose only job is SSH-to-remote-machine + relay ("hibana-interpreter"). Role handles the routing; no per-request SSH instructions.
- **Morning-ops workflow:** crons fire briefs → operator reads latest-message previews per bot → drives by exception. "You opened Desktop twice. No re-prompting."
- Refs: hermes-agent.nousresearch.com/docs/desktop · github.com/NousResearch/Hermes-Bot-Mode (archived 17-ago, integrated into Desktop) · cron docs.

## B. Tony Simons — Hermes Desktop Masterclass (parts 1-4, 18-22 ago)
Part 1 What Desktop actually is: https://x.com/tonysimons_/article/2089875358804054244
Part 2 Install/config properly: https://x.com/tonysimons_/article/2090225007159112017
Part 3 Mastering the workspace: https://x.com/tonysimons_/article/2090594877352657234
Part 4 Profiles: https://x.com/tonysimons_/status/2091010077063004510

Key transferable ideas (beyond Hermes-specific plumbing):

1. **Layer ownership discipline** (P1/P2): Electron shell ≠ React renderer ≠ agent runtime; "which layer owns the thing I just changed?" is the debugging question. Runtime health ≠ inference health — two separate gates. Readiness is an explicit signal (`HERMES_BACKEND_READY port=N`), never "the window opened".
2. **Session = the durable unit of work** (P3): sessions outlive windows; stored conversation ≠ live runtime attached to it; cached transcript tail is a "visual head start", backend state stays authoritative and is reconciled. "I can see my old messages" and "fully reconnected" are different states.
3. **Composer as control surface** (P3): three verbs while an agent works — **/steer** (redirect the active turn), **/queue** (park next job; inspectable/editable before it runs), **Stop** (halts AND parks the queue instead of firing the next item).
4. **Keep the transcript out of landfill territory** (P3): files/previews/artifacts live beside the chat, not in it. Product mode vs Technical mode for tool activity ("transparency doesn't mean JSON has breached containment").
5. **Profiles** (P4): Session=what, Project=where, Profile=WHICH persistent agent environment (own memory, skills, MCP, model defaults, cron state, credentials). Profiles are a Hermes state boundary, NOT an OS boundary (shared filesystem/CLI creds by default; provider auth falls back to root store deliberately). Last-click-wins race protection on switching; multiple profiles run concurrently. Rule: **create a profile only when the separation itself should persist**; capability separation (the env that can publish ≠ the env for experiments) is a legitimate boundary. Gateway → Profile → Session hierarchy; "a Bot IS a Profile" (Part 5 = Bot Mode).
- P1 also links his 12-part Hermes Agent Masterclass roadmap (20 jul): https://x.com/tonysimons_/status/2082268682772734461

## C. Tony Simons — "Hermes Agent Just Learned How to Stop" (17 ago)
https://x.com/tonysimons_/article/2089482171409117219

- The under-measured benchmark: **what happens when the human changes their mind mid-run**.
- Fix was in the sequential EXECUTOR, not one tool: long-running tools moved to a worker; interrupt state checked ~1/sec; cooperative tools get a grace period; otherwise the call is marked cancelled and the loop moves on.
- **Zombie-result rule:** once cancelled, a late-finishing worker result must never re-enter the conversation as success. "Cancelled stays cancelled in the agent's reality."
- Two protection layers: global executor backstop + local cooperative shutdown inside tools.
- Thesis: "Capability gets attention. Autonomy gets demos. Control is what makes either usable."

## D. dzhng (David, @duetchat) — "Building software factories (with no slop)" (19 ago)
https://x.com/dzhng/status/2090252351533973768 (article 2090141685116510208) — 274k views

- **Slop is not a model-quality problem**: it's what happens when generation is unbounded and verification bottlenecks on human reading. When supply >> inspection capacity, review becomes a formality ("LGTM").
- Code will get LESS readable over time (Claude-speak / AI-native languages / machine code); reviewers pinned to the artifact become less relevant every quarter.
- **Treat the codebase as a black box; treat review as an interpretability problem.** Domain-specific pieces with well-defined inputs/outputs; sensors at the seams; interrogate constantly. "The interface becomes the review surface."
- Artifacts that must stay human-readable regardless of the code: **Invariants, Traces, Attack surface, Decisions.**
- **Decision ledger (the core pattern):** every agent session hands back a ledger of every decision made where the spec was silent — plain language, ranked least-confident first, incl. what it would have asked if asking were free. "A two-day run produces tens of thousands of lines I will never audit, and maybe thirty decisions that determine whether the thing is right. I read the thirty. I push back on four."
- **Auditor rules:** separate pass from the implementer (independent subagent — a model reviewing its own work rationalizes); the audit NEVER blocks and CANNOT change code (else it optimizes for a clean report, not an honest one).
- **The hard part is slicing** into independently verifiable pieces; harder still is knowing where the pieces are → **fog-of-war scouting**: sweep quadrant by quadrant (known/unknown/blindspot), hand back rendered options + decision tables, carve territories, re-slice when a territory hides more map.
- Loop: Map the fog → Codify (spec = transcription, decisions made upstream where cheap) → Build (harness in loop mode, reviews per slice, plan re-slices itself) → Review the choices (ledger, least-confident first).
- Evidence: one unattended run of 1 day 16 h; "I reviewed the ledger, not the diff." (repo README claims a 40 h run.)
- Skills repo: https://github.com/dzhng/skills — 11 engineering skills (explore-unknowns, write-spec, implement-spec[-with-codex], close-spec, refactor-clean, write-tests, audit-performance, write-docs, code-review, **audit-choices**) + visual-review skills (screenshot baselines "telemetry-based, not vibes-based") + write-skills/eval-skills with golden-case evaluation.

## F. Hermes cron docs (hermes-agent.nousresearch.com/docs/user-guide/features/cron)
- Unified `cronjob` tool; one-shot or recurring; pause/resume/edit/trigger/remove. Gateway ticks scheduler every 60 s; jobs run in **isolated agent sessions** (no chat history — prompts must be self-contained).
- **`no_agent=True`:** script-only jobs, stdout delivered verbatim — "No tokens, no model, no provider fallback." (zero-token watchdogs).
- **Pre-run gates:** attach a script with `wakeAgent` logic; emit `{"wakeAgent": false}` → skip the LLM at $0.
- **Chaining:** `context_from` pipes job outputs (collect → filter → format); `continuity=true` for dedup in recurring scouts.
- Result delivery routed to `origin`/`local`/`telegram`/`discord`/`slack`/`all`. Per-job model pins. Cron runs cannot create other cron jobs.
