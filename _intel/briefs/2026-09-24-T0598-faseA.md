## AC2 — Contrato de findings JSON
`_intel/automation-findings/<task>-<YYYYMMDD[-HHMM]>.json`:
```json
{ "task": "string", "repo_owner": "string", "actionable": true, "summary": "string",
  "evidence": "string", "severity": "low|medium|high|critical", "fingerprint": "string (opcional)",
  "kind": "string (opcional, default general)" }
```
Fingerprint: si `fingerprint` viene explícito se usa tal cual; si no, se deriva como
`sha256(task + "|" + normalize(summary)).slice(0,16)` con `normalize` = trim + lowercase +
colapsar espacios. Documentado y validado en `src/automation-finding-schema.cjs`.

## AC3 — Router `scripts/automation-router.cjs`
- Escanea `_intel/automation-findings/*.json` (o `--file <path>` puntual).
- JSON inválido / falta `repo_owner` (u otro campo requerido) → cuarentena
  (`_intel/automation-findings/quarantine/`) + log (`router-log.jsonl`), nunca tira el proceso.
- `actionable:false` → solo log (`non-actionable.jsonl`), sin tarjeta, sin send; archivo movido a
  `processed/`.
- `actionable:true` → UNA tarjeta ready en el repo dueño vía `_docs-curation/ledger.cjs create
  --origin <fingerprint>` (ledger YA es idempotente por `origin_key` — reimportar el mismo
  fingerprint devuelve la tarjeta existente en vez de duplicar) + `a2a_send` al carril dueño vía
  `bin/a2a-send-cli.cjs` con `--corr <cardId>`. Estado de "delivered" por fingerprint se persiste
  en `_intel/automation-findings/.router-state.json` para que un fallo de a2a NO duplique la
  tarjeta en la corrida siguiente (reintenta solo el send). Archivo se mueve a `processed/` recién
  cuando delivered:true.
- Ledger CLI y a2a CLI son inyectables (`--ledger-cli`, `--a2a-cli`, o env
  `WEZBRIDGE_AUTOMATION_LEDGER_CLI` / `WEZBRIDGE_AUTOMATION_A2A_CLI`) para que los tests usen
  dobles y NUNCA toquen el ledger real ni manden a2a reales.

## AC4 — helper `bin/emit-finding.cjs`
`node bin/emit-finding.cjs --task X --repo Y --actionable true --summary "..." --evidence "..."
[--severity high] [--kind ...] [--fingerprint ...] [--out-dir <dir>]` escribe un finding válido
con el nombre `<task>-<timestamp>.json`. Un solo one-liner para que Fase B migre cada automatización.

## Tests (fail-first)
`test/automation-router.test.cjs`, 6 casos exigidos por el brief:
1. actionable → 1 tarjeta ready (owner repo) + 1 a2a send delivered:true (doble).
2. mismo finding 2 corridas → sigue 1 sola tarjeta.
3. no actionable → 0 tarjetas, 0 sends, 1 línea de log.
4. archivo inválido → cuarentena.
5. falta `repo_owner` → cuarentena.
6. falla el a2a → tarjeta igual creada, reintenta el send la corrida siguiente, sin tarjeta duplicada.
