# T-0596 — a2a_send transport: Orca terminals (identity + delivery)

Copy of the dispatched card brief, plus the worker's plan/log. See the original
prompt text in the orchestrator's dispatch — summarized here for the record.

## Problem
Fleet panes now live in Orca terminals; wezbridge's `src/pane-identity.cjs` and
`src/verified-send.cjs` only know WezTerm, so `a2a_send({to_project})` resolves
`resolved_pane:null` and the durable queue never delivers. Full analysis:
`wezbridge/artifacts/2026-09-24-orca-vs-wezterm.html`. Operator chose the HYBRID:
Orca as TRANSPORT only, ledger stays the sole authority.

## Scope (this card)
1. Identity: `pane-identity.cjs` resolves `to_project`/lane names to a live Orca
   terminal handle when WezTerm has no live pane (WezTerm keeps precedence).
2. Delivery: `a2a_send` delivers to an Orca terminal via `orca terminal send`
   with a stable, queue-entry-derived `--retry-request` id, plus a screen
   read-back for verification. All existing a2a_send controls (dispatch gate,
   result-shape check, lease, queue, audit) are preserved — Orca is only the
   last hop.
3. `a2a-results.jsonl` / queue delivery records carry `transport: "orca"|"wezterm"`.

Out of scope (explicit): re-delivering the 30 old approvals; task_router.py /
notify_orchestrator.py rewiring; Orca Runs/Tasks/gates; project-queue.cjs's
`createConsumer`/queue-drain resolver (separate call site, still WezTerm-only —
not literally the a2a_send code path this card touches, and the brief
explicitly scoped widening to "if it's the same code path").

## Plan
1. `src/orca-send.cjs` (new): `sendToOrcaTerminal(handle, body, {retryId, ...})`
   — last-hop primitive, `orca terminal send --enter --wait-submit --retry-request`
   then a `orca terminal read --screen` read-back verification. Returns the same
   submitted/delivered vocabulary as `verified-send.cjs`'s `classifyDelivery`.
2. `src/pane-identity.cjs`: add `resolveOrca(wanted, terminals, aliasMap)` —
   lane name > cwd (worktreePath leaf) > title precedence, mirroring `resolve()`.
   `resolve()` itself (WezTerm) is untouched.
3. `src/mcp-server.cjs` `a2a_send`: when `pane-identity.resolve()` finds no live
   WezTerm pane for `to_project`, try Orca (live census via `orca-census.cjs` +
   lane roster via `lane-roster.cjs` for the `lane` field) before falling back
   to queue-only. On an Orca hit: deliver via `orca-send.cjs` instead of
   `verified-send.cjs`; record `transport` in the event, the result body, and
   the queue line.
4. `src/a2a-intel.cjs` `recordResultBody`: optional `transport` param.
5. `src/project-queue.cjs` `enqueue`: optional `transport` field (additive —
   omitted entirely on legacy/untransported calls, so no reader that doesn't
   know the field breaks).
6. Tests: `test/pane-identity-orca.test.cjs`, `test/orca-send.test.cjs` (unit,
   injectable runOrca, no real CLI), `test/a2a-send-orca-transport.test.cjs`
   (mcp-server spawned subprocess, WezTerm mock + `test/mocks/orca-mock.cjs`
   fake CLI, fail-first before the fix).
7. Real smoke: `a2a_send to_project="wezbridge" type=progress` with an
   "ignorar" body, evidence pasted in the close report.
