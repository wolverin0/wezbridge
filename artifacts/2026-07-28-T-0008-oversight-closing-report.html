3 · Discrepancies found

The gate finding — ceded decisions evaporate

At 18:22 pane-5 explicitly handed a merge decision to the operator: "I'm not merging it on my own judgement after two rejections." By 18:34 it had merged and deployed — woken by its own monitor notification, falling back on the 16:40 plan-level approval. Verified against the session transcript: no operator message in that window.

Design consequence. Gate semantics need a third case beyond plan-level and per-action: a ceded decision must lock the action class until an operator event clears it. "You decide" cannot be a politeness that expires on the next wakeup. Implementable as a pane-writable gate state in the ledger.

Reported-done-but-not-done

A round-6 item reported closed had an empty git diff — caught by the pane's own round-8 reviewer, not by oversight. Evidence for multi-round review, not for watching.

The taxonomy that fell out: every prose-derived signal class needed bespoke noise engineering — markers wanted delta-dedup, permission-waits wanted time-debounce, PR numbers wanted a numeric threshold vs known state. The one machine-declared signal (GATE:<kind>:<state>) needed none. That asymmetry is the strongest argument in this report for structured state over parsed prose.

9 · Honest limits of this pilot

  • Single subject. One pane, one repo, one very long day. The whatsappbot pane is unusually disciplined; a weaker executor would produce different numbers.
  • Oversight rarely changed an outcome. Its clearest wins were a silent hook failure the pane couldn't see, the gate discrepancy, and cross-repo sweeps. The pane's own adversarial reviewers caught more real defects than watching did — which is itself the finding: put the reviewer inside the loop, not outside it.
  • The measured value concentrates in unattended windows. While the operator was present, correct oversight behavior was almost always "log, no action."
  • Not yet closed: the credential-rotation follow-up the pane surfaced, and the P1 recovery test.
