This very session proved it — a week-long orchestrator that depleted context and needed /handoff. The graph-era fix isn't "more agents"; it's sessions disposable, files durable, control plane thin.

3 · The monitoring.md orchestrator vision, restated in graph terms

Your original design — orchestrator pane watches all panes, pokes stalls, decides within rules, Telegram-escalates criticals — is exactly what the blackboard thread calls a control plane. We own every component already:
  • HAVE Monitor tool (pane watching) · a2a-heartbeat.cjs (5-min silence SLA) · telegram-streamer + ntfy (escalation) · safety-policy.cjs (decision rules) · monitoring.md fleet-wide fresh (per-repo signals, as of Phase B) · session-snapshot (crash durability) · project-status-registry
  • MISSING The standing loop that survives me. Today the orchestrator = whichever Claude session is awake, holding fleet state in its context window. When context depletes (this week: twice), the control plane dies with it and /handoff is the parachute. The graph-era correction: the orchestrator pane should be a thin re-derivable reader of durable files — any fresh session reads ledger + dashboard and IS the orchestrator within 30 seconds, no 40-message warmup, no heroic handoffs.
This also merges cleanly with Phase C: the velocity-aware sweeper is just the first deterministic node of that control plane (freshness watching); stall-poking and Telegram escalation are two more nodes on the same ledger. One design, not two.

4 · Adoption plan (proposed — nothing built yet)

P0 A2A result envelope v2 — add optional structured tail to type=result: criteria: [pass/fail+evidence], files_changed, validated_by, next_action. Update docs/a2a-protocol.md + both AGENTS.md. Cost: ~1h, pure convention, no code. Immediately makes every fleet dispatch machine-checkable.

P0 Knowledge-compiler rule — one paragraph in global CLAUDE.md + ~/.codex/AGENTS.md: "A correction that recurs ≥2× or was explicitly given by the operator MUST produce an enforcement artifact (test / lint / hook / guard / skill) — an MM claim alone is the fallback, not the destination." Cost: minutes. This is the single highest-leverage idea in all three sources.

P1 Fleet task ledger + FSM — .orchestrator/tasks/*.json (7 states, leases, acceptance criteria) + dashboard.md regenerated from tasks; orchestrator sessions become disposable readers of it. Design it WITH Phase C (sweeper = first consumer). Cost: ~1 day. This closes the real gap.

P1 verify:agent per repo — one command per Tier-1 repo that runs its lint+types+tests+smoke. Natural add to project-health --apply (it already knows each repo's commands). Feeds envelope v2's validated_by.

P2 Workflow-profile taxonomy — name our implicit tiers (Direct/Quick/Feature/Initiative/High-risk) in CLAUDE.md so dispatch prompts can request ceremony proportionally.
P2 Micro-practices from 0xRafy — merge-node-as-real-agent, per-node state contracts (reads/writes) in Workflow scripts, few-shot examples in router prompts.

5 · Explicitly rejected

  • Installing Ruflo/LangGraph/CrewAI — even the ChatGPT thread rejects the 98-agent Ruflo surface; our Workflow tool + panes already cover coordination. Same verdict as LobeHub.
  • BMAD/GSD wholesale — cherry-pick the proportionality idea only; we have skills+claims+handoffs covering the rest, and three competing roadmap systems is the anti-pattern the thread itself warns about.
  • Retiring /goal and /loop — false framing in the article. A loop is the engine inside a graph node; the graph is the wiring between nodes. We keep both layers.
  • Vector/claim memory as authority — thread agrees with our standing rule: MM suggests where to look; code, tests and git are truth.
  • Hooks doing orchestration — hooks stay deterministic adapters (inject/validate/gate). We already learned this the expensive way (git-hook plague).
