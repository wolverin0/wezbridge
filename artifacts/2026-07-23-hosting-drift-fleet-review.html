Pattern learned (feeds the knowledge compiler)

  • monitoring.md is treated as "what is this project" by every agent — so even deliberately local-scoped contracts MUST name the production host as out-of-scope context. 5 of 11 repos failed this (pedrito, omniremote, venezia, mutual, nereidas).
  • Hosting claims in prose/comments rot silently: pedrito's "AWS" comment, omniremote's ":8080 in production", mutual's Nginx guide, venezia's pm2 runbook, whatsappbot's Otacon doc. None of these are executable, so nothing ever failed when they went stale — exactly the class the greppable-headers + doc-triage system exists for.
  • The worst failure mode isn't silence — it's wrong remediation: omniremote's watchdog scripts would spawn a local process and claim success during a production outage.
  • Gold standards to copy: bajoneando (host + tunnel + SSH details in monitoring.md matching HANDOFF.md) and whatsappbot (server/ssh_prefix in frontmatter + dependency table).
